## 1. Purpose

Define the **secure software development lifecycle (SDLC)** and **coding standards** for iConnect Plus. Source may live on GitHub; **production runtime** is on Cache Digitech premises.

## 2. SDLC phases

| Phase | Activities | Security gates |
|-------|------------|----------------|
| Requirements | BRD/FRD in `docs/01_BRD`, `docs/02_FRD` | Privacy/security stories identified |
| Design | SDD, Architecture Lock compliance | Threat notes for new integrations |
| Implementation | Feature branches, PR review | Lint, type-check, architecture CI |
| Test | Unit + integration tests | No secrets in tests |
| Release | Tagged deploy to on-prem host | Change record (§2.4) |
| Operate | Monitor, patch, backup | VAPT remediation (§2.6) |

## 4. Coding standards — backend (Python)

| Topic | Standard |
|-------|----------|
| Style | Ruff / project formatter settings |
| Types | Type hints on public service methods |
| SQL | SQLAlchemy 2.0; no raw SQL in routers |
| Secrets | Never commit; use `settings` from env |
| Crypto | Use platform encryption helpers; no custom ciphers |
| Errors | HTTPException with safe messages (no stack to client) |
| Dependencies | Pin in `requirements`; SBOM §2.7 |

## 5. Coding standards — frontend (TypeScript)

| Topic | Standard |
|-------|----------|
| Stack | Next.js 16+, Tailwind, ShadCN |
| UI system | `ui-ux-pro-max` + `design-system/enterprise-erp-platform/` |
| Auth | Cookie-based session; no token in localStorage |
| Permissions | Mirror API codes in `modules.ts` |
| XSS | React escaping; sanitize rich text per module policy |

## 6. Forbidden patterns (Architecture Lock)

| Forbidden | Alternative |
|-----------|-------------|
| Business logic in routers | Services |
| Cross-module ORM access | Platform ports / facades |
| Physical DELETE on business data | Soft delete |
| Direct UI → database | API only |
| NestJS / Prisma / Mongo primary | Locked stack |
| Bypass workflow/audit/notify | Outbox engines |
