## 1. Purpose

Guide **administrators** operating iConnect Plus on Cache Digitech **on-premises** infrastructure: user lifecycle, RBAC, tenant settings, and coordination with IT for VPN/LAN access.

## 2. Administrator types

| Role | Scope |
|------|-------|
| **Tenant Admin** | Users, roles, settings within one tenant |
| **Super Admin** | Cross-tenant platform operations (restricted) |
| **IT Admin** | Host, VPN, backups, Docker — not daily business data |

## 3. Access requirements

| Task | Network |
|------|---------|
| Admin UI | LAN or **VPN** → internal HTTPS URL |
| Server SSH | IT break-glass only |
| Database | No routine direct access — use API and approved tools |

Production URLs are **internal** — do not publish to public DNS.

## 4. User management

| Action | Steps |
|--------|-------|
| Create user | Foundation → Users → invite/create; assign email |
| Assign roles | Map user to `TENANT_ADMIN` or module roles per **3.1 RBAC Matrix** |
| Enable MFA | User profile → enable TOTP; user scans QR in authenticator app |
| Disable user | Deactivate account; sessions invalidated on next request cycle |
| Unlock after lockout | Wait 15 minutes or admin reset per policy — **Template / Pending sign-off** |
| Password reset | Trigger reset flow; never set or email cleartext production passwords |

Lockout defaults: **5** failures, **15** minute lock (`ACCOUNT_LOCKOUT_THRESHOLD` / `ACCOUNT_LOCKOUT_MINUTES`).

## 5. Role & permission management

- Permissions follow `{module}.{resource}:{action}` codes.  
- UI routes must match API permissions (CI gate in development).  
- Deny-by-default: missing permission blocks API calls.  
- System roles: `SUPER_ADMIN`, `TENANT_ADMIN` — assign sparingly.

See **3.1 RBAC Matrix** for module role patterns.

## 6. Security configuration (tenant-level)

| Setting | Guidance |
|---------|----------|
| Demo login | Must be **disabled** in production (`ALLOW_DEMO_LOGIN=false`) |
| API documentation | Disabled in production (`ENABLE_API_DOCS=false`) |
| SSO (Entra) | Optional — configure OAuth only if approved (4.5 processors) |
| Session duration | JWT access/refresh lifetimes via environment — IT + Platform |

## 7. Data classification (admin awareness)

| Class | Admin handling |
|-------|----------------|
| public | Standard |
| internal | Share only inside organisation |
| confidential | Need-to-know; customer/HR data |
| restricted | Payroll, bank, tokens — minimal export |

Encrypted fields (PAN, bank, etc.) are not visible in logs — do not attempt to export via unsupported tools.

## 8. Soft delete & retention

Business records use **soft delete** — deleted records remain for retention periods (**3y** operational default, **10y** audit class, etc.). Purges are automated platform jobs — see **4.3**. Legal hold process: **Template / Pending sign-off**.

## 9. Incident handling (admin)

| Event | Action |
|-------|--------|
| Suspected account compromise | Disable user; notify IT / platform (5.4 PB-01) |
| Data leak suspicion | Preserve audit logs; escalate to DPO |
| Application outage | Check status with IT; reference **5.6 Runbook** |

CERT-In reporting is handled by designated Cache Digitech PoC — **Template / Pending sign-off**.

## 10. Backup & restore (coordination)

Administrators do **not** run production restores. Request IT using **4.4** after approval. UAT refresh requires **4.6** masking.

## 11. Deployment & releases

Platform team deploys via Docker Compose on internal host (**5.6**). Tenant admins receive maintenance notices — **Template / Pending sign-off** communication template.
