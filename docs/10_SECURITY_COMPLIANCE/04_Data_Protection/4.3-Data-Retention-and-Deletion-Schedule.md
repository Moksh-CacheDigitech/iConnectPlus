## 1. Purpose

Define **retention windows**, **purge mechanisms**, and **deletion semantics** (soft delete vs hard purge) for iConnect Plus data on on-premises PostgreSQL and related stores.

## 2. Principles

| Principle | Implementation |
|-----------|----------------|
| Business records | Soft delete on transactional tables — no physical DELETE in normal operations |
| Legal / audit hold | Suspend purge when hold flag/process active — **Template / Pending sign-off** |
| Automated purge | Celery jobs: `platform.outbox_purge`, `platform.retention_purge` |
| Tenant isolation | Purge scoped by tenant where applicable |

Authoritative retention constants: `apps/api/src/modules/platform/retention.py` — `RETENTION_DAYS`.

## 3. Platform retention schedule

| Class key | Retention | Applies to | Purge mechanism |
|-----------|-----------|------------|-----------------|
| `operational` | **3 years** (1095 days) | Default soft-deleted operational rows | Domain jobs / future automation — **Template / Pending sign-off** per table |
| `audit` | **10 years** (3650 days) | Audit log and audit-class records | Archive then purge policy **Template / Pending sign-off** |
| `notification` | **1 year** (365 days) | `NtfEvent` and similar | `platform.retention_purge` |
| `outbox_processed` | **90 days** | Processed outbox rows | `platform.outbox_purge` |
| `session` | **30 days** | Session / refresh cleanup window | Session service + scheduled cleanup |

Additional platform purges (same job family):

| Artifact | Retention | Task |
|----------|-----------|------|
| Idempotency records | 30 days | `platform.retention_purge` |
| Job run history | 90 days | `platform.retention_purge` |

## 4. Module-specific retention

| Domain | Policy | SSOT |
|--------|--------|------|
| Document management | Per `DocRetentionPolicy` (tenant-configurable days) | Document module + migrations |
| HR / finance / payroll | Operational + statutory — align with 3y/10y classes | Module owners + legal |
| Logs (application) | ≥ **180 days** on-prem | See 5.1 |

Document module example seed uses long retention (e.g. 2555 days) for demo policies — production values are tenant-defined.

## 5. Deletion types

| Type | Description | User-visible |
|------|-------------|--------------|
| Soft delete | `is_deleted`, `deleted_at`, `deleted_by` | Hidden from default lists; recoverable per module |
| Hard purge | Physical row removal after retention cutoff | Not reversible |
| Object delete | MinIO object removal after document retention/archive | Per document workflow |

## 6. Data subject / erasure requests (DPDP)

| Step | Action | Owner |
|------|--------|-------|
| Intake | Ticket to DPO / admin | **Template / Pending sign-off** PoC |
| Verify identity | Tenant admin or DPO process | Tenant admin |
| Execute | Soft delete + anonymize fields where erasure required | Platform + module owner |
| Evidence | Record in processing register (4.5) | DPO |

Statutory retention may **override** erasure for finance/audit classes — legal review required.

## 7. Backup retention
