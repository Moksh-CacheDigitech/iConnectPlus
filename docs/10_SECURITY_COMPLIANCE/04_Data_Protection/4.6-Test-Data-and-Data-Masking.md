## 1. Purpose

Define rules for **non-production data**: synthetic fixtures, masked copies of production, and prohibitions against using live **restricted** personal data in dev without approval.

## 2. Environment data policy

| Environment | Allowed data | VPN / network |
|-------------|--------------|---------------|
| Development | Synthetic seeds (`seed_demo_modules.py`), fabricated PII | Local / dev VLAN |
| Test / UAT | Masked subset or full synthetic | VPN for remote |
| Production | Live data | LAN / VPN only |

Prod → Dev direct copy: **prohibited** unless explicit DPO + IT approval (2.3).

## 3. Masking requirements

When refreshing UAT from production backup, apply at minimum:

| Field type | Masking rule |
|------------|--------------|
| Email | Replace domain with `@example.invalid`; preserve uniqueness |
| Phone | Random 10-digit invalid range |
| PAN / Aadhaar / tax IDs | Replace with test values; re-encrypt with UAT Fernet keys |
| Bank account | Tokenize to non-routable test numbers |
| Names | Faker or fixed catalog — no real employee names |
| Passwords | Reset to known test password (bcrypt) — never prod hash |
| JWT / API secrets | Regenerate all secrets in UAT `.env` |

**Masking script / tool:** **Template / Pending sign-off** (owner: Platform).

## 4. Synthetic data

| Source | Use |
|--------|-----|
| Demo seed scripts | Local dev, demos |
| Factory builders in tests | CI unit/integration |
| Manual CSV imports | UAT scenarios — must pass masking checklist |

## 5. Encrypted fields

Masked exports must either:

1. Decrypt with prod keys → mask → re-encrypt with UAT keys, or  
2. Null out restricted columns in UAT refresh.

Never copy production `.env` encryption keys to UAT.

## 6. MinIO / attachments

| Control | Action |
|---------|--------|
| Documents with PII | Exclude from UAT refresh or scrub binaries |
| Bucket | Separate UAT bucket/volume |
| ClamAV | Same as prod target in UAT |
