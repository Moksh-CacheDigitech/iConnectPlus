## 1. Purpose

Document **business continuity** and **disaster recovery** for iConnect Plus when primary on-premises infrastructure at Cache Digitech premises is unavailable. **Primary DR strategy is on-premises** (secondary host, cold/warm standby, or DR site) — not AWS RDS/S3 failover as default.

## 3. DR architecture (on-prem)

| Component | Primary | DR (target) |
|-----------|---------|-------------|
| App host | SRV-ERP-01 | SRV-ERP-02 or spare hardware — **Template / Pending sign-off** |
| PostgreSQL | Volume `erp_pgdata` | Restored dump on DR host |
| MinIO | `erp_minio_data` | Mirrored backup restore |
| Secrets | Primary `.env` | Encrypted copy in IT vault |
| DNS / URL | Internal IP or hostname | Same IP on DR or manual DNS update |
| VPN | Users reach LAN | Unchanged — must reach DR IP |

**Cloud DR standby:** Optional — **not primary** in v2.0 model.

## 5. Activation criteria

| Condition | DR decision |
|-----------|-------------|
| Primary host hardware failure | Activate DR restore |
| Site unavailable (fire, flood) | DR site + backups offsite on-prem |
| Ransomware on primary | Clean DR rebuild from pre-incident backup |
| Corrupted database | Point-in-time restore if WAL available — else last good dump |

**Authority to declare DR:** **Template / Pending sign-off** (role).
