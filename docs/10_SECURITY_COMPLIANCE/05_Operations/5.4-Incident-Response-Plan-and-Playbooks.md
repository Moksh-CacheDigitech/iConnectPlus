## 6. Response phases

```text
Detect → Triage → Contain → Eradicate → Recover → Post-incident review
```

| Phase | Key actions |
|-------|-------------|
| Detect | Alerts (5.1), user report, IT monitoring |
| Triage | Classify severity; assign IC; preserve logs |
| Contain | Isolate host/VLAN; disable accounts; block IOC |
| Eradicate | Patch, remove malware, rotate secrets (4.2) |
| Recover | Restore from backup (4.4); validate integrity |
| Review | Timeline, root cause, CAPA, update runbooks |

## 7. Playbooks

### PB-01 — Suspected credential compromise

| Step | Action |
|------|--------|
| 1 | Disable affected user(s); force password reset |
| 2 | Invalidate sessions (`sec_session` / refresh tokens) |
| 3 | Review auth logs for source IPs |
| 4 | Rotate `JWT_SECRET_KEY` if widespread — maintenance window |
| 5 | Notify DPO if personal data accessed |

### PB-02 — Ransomware / host compromise

| Step | Action |
|------|--------|
| 1 | Disconnect host from LAN (not internet SaaS — internal isolation) |
| 2 | Preserve disk / memory if forensics required |
| 3 | Activate DR path (5.5) from clean backup |
| 4 | CERT-In notification if applicable |
| 5 | Full secret rotation |

### PB-03 — Data exfiltration via API

| Step | Action |
|------|--------|
| 1 | Enable verbose audit; identify API keys/users |
| 2 | Rate-limit / block IP at nginx or firewall |
| 3 | Revoke tokens; patch authorization gap |
| 4 | Assess personal data scope for 4.5 / 6.3 |

### PB-04 — PostgreSQL failure

| Step | Action |
|------|--------|
| 1 | Check container and disk |
| 2 | Failover to DR instance if configured |
| 3 | Restore from latest dump (4.4) |
| 4 | Communicate RPO achieved |

### PB-05 — Malicious file upload

| Step | Action |
|------|--------|
| 1 | Quarantine object in MinIO |
| 2 | Verify ClamAV definitions updated |
| 3 | Scan related uploads; review AV logs |
