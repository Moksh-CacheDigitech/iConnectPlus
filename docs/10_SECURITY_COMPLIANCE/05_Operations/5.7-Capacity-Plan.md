## 4. Component sizing guidelines

| Component | Sizing note |
|-----------|-------------|
| PostgreSQL | Largest consumer — SSD required; monitor `erp_pgdata` |
| MinIO | Plan 2–3× current object size for headroom |
| Redis | Memory ∝ cache keys; session load moderate |
| RabbitMQ | Disk for persistent queues if used |
| API | Scale vertically first (more CPU/RAM to host) |
| Celery workers | Add worker container or `--concurrency` before second host |
| nginx | Low footprint |
| ClamAV | RAM for defs; CPU on scan spikes |

**Horizontal second app host:** Evolution-gated — not default monolith split.
